# Architecture — VN Traffic Law RAG MVP

This document describes the implementation that is currently served by this repository.

## Data and ingestion

- **Source manifest:** `data/sources/manifest.json` lists legal documents. Each entry points to a Markdown file below `data/corpus/mds/` and carries document identity, source, and legal metadata.
- **Document model:** `backend/app/ingestion/markdown.py` loads Markdown into LangChain `Document` objects. Heading-aware chunking preserves article, clause, and point metadata, plus source and effective-date fields.
- **Chunk command:**

  ```bash
  uv run --project backend python backend/scripts/fetch_sources.py
  ```

  Defaults are `data/sources/manifest.json`, `data/corpus/mds/`, and `data/processed/chunks.jsonl`. Override them with `--manifest`, `--local-dir`, and `--output`.

## Retrieval index

`backend/scripts/index.py` creates a fresh local Qdrant collection from the chunk JSONL:

```bash
uv run --project backend python backend/scripts/index.py
```

The index is a LangChain Qdrant **HYBRID** store:

- dense OpenRouter embeddings with 768 dimensions;
- sparse FastEmbed BM25 (`Qdrant/bm25`);
- Qdrant local persistence at `QDRANT_PATH` (default `backend/data/processed/qdrant` in application settings);
- collection name from `QDRANT_COLLECTION` (default `traffic_law`).

The index is derived data. Rebuild it from the Markdown manifest and chunks rather than treating it as the source of truth.

## Request flow

```text
Markdown manifest + files
  -> LangChain Documents with legal metadata
  -> chunks.jsonl
  -> local Qdrant HYBRID (dense 768 + FastEmbed BM25)
  -> deterministic reference/evidence checks
  -> configured ChatOpenRouter model
  -> answer with metadata-derived citations
```

`GENERATION_MODEL` selects the configured ChatOpenRouter model (default: `deepseek/deepseek-v4-flash-0731`). `OPENROUTER_API_KEY` and `OPENROUTER_BASE_URL` configure the provider. The generator receives the question and retrieved documents; citation fields are built from stored metadata, not generated by the model. If evidence is insufficient, the service abstains instead of fabricating an answer or searching the web.

## Legal intelligence

The active RAG path supports:

- Vietnamese legal structure metadata: document, article, clause, and point;
- source and retrieval provenance in citations;
- explicit `effective_date` queries;
- deterministic reference matching and evidence sufficiency checks;
- grounded generation and verified-or-abstain behavior;
- legal document listing, provision filtering, and metadata search.

## Supabase application persistence

Supabase stores application data, not the local retrieval corpus. The active persistence layer covers profiles/authentication, chat sessions, messages, feedback, and bookmarks. Qdrant holds derived retrieval vectors and sparse terms locally; Markdown and its manifest remain ingestion inputs.

## HTTP API

FastAPI mounts these active routes:

- `GET /api/v1/health` — service health;
- `GET /api/v1/health/live` and `GET /api/v1/health/ready` — liveness/readiness;
- `POST /api/v1/chat` — grounded legal chat (`question`, `top_k`, optional `effective_date`);
- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me` — Supabase auth;
- `GET/POST /api/v1/chats`, `GET/PATCH/DELETE /api/v1/chats/{session_id}` — chat sessions;
- `POST /api/v1/chats/{session_id}/messages` — persist a message;
- `POST /api/v1/chats/{session_id}/messages/{message_id}/feedback` — persist feedback;
- `POST /api/v1/chats/{session_id}/bookmarks` — persist a bookmark;
- `GET /api/v1/legal-documents` and `GET /api/v1/legal-documents/{document_id}` — browse documents;
- `GET /api/v1/legal-documents/{document_id}/provisions` — filter provisions;
- `GET /api/v1/legal-search` — search legal chunks and metadata.

Run the API from the repository root:

```bash
uv run --project backend uvicorn app.main:app --reload
```

## P2 paused scope

P2 work is paused. It is not part of the active runtime contract: no additional ingestion orchestration, external retrieval, autonomous agent workflow, or expanded review platform should be inferred from this MVP. The active implementation is the Markdown → LangChain Documents → local Qdrant HYBRID → configured ChatOpenRouter path described above, with Supabase limited to application persistence.
